# 第三方音乐客户端

[English](subsonic.en.md) · [使用指南](using-flaretune.md)

FlareTune 提供 Subsonic 1.16.1 的音乐兼容接口和 OpenSubsonic 歌词扩展。目前已完成本地自动化验证，**本版本尚未完成音流等真实客户端验收**，不承诺所有 Subsonic 客户端均可用。

## 连接

1. 在网页打开「设置 → 个人设置 → 第三方音乐客户端」。
2. 打开「允许 Subsonic 客户端连接」，输入当前登录密码验证。
3. 在音流或其他客户端选择 **Subsonic**，服务器地址填写 FlareTune 站点根地址（例如 `https://music.example.com`，不加 `/rest`）。使用原用户名和密码，认证模式选择 **token/salt（令牌）**。
4. 使用原始音质，关闭客户端的服务端转码/码率限制选项。

开关默认关闭。自己修改密码或管理员重置后自动关闭；用新密码登录网页，再验证开启。关闭开关后新的播放、下载及其他接口请求均拒绝；客户端已经缓存的文件不会因此从设备删除。账号停用或必须改密时也拒绝访问。

为兼容 token/salt 登录，开启时会在服务端额外保存一份 AES-GCM 加密的密码副本；网页登录仍使用原来的不可逆密码哈希。关闭、改密、重置会删除副本。副本按账号及密码版本绑定，使用与 AI 密钥不同的派生加密密钥；轮换 `SETUP_SECRET` 后需重新验证开启。密码不会从开关查询接口返回，也不写入网页持久化存储。

## 首版能力与限制

支持曲库浏览、搜索、原文件播放/下载、HTTP Range 拖动、封面、已有规范化 R2 歌词、歌曲收藏、私人普通歌单增删改查。收藏与歌单同网页双向可见；普通歌单最多 50 个，每个歌单最多 500 首且同歌不重复，沿用网页限制。专辑/歌手收藏不支持。

不提供实时转码、封面缩图、播放次数上报、播放历史/队列同步、共享歌单、播客、视频、账号或曲库管理。`scrobble` 返回不支持，播放/下载不会增加网页播放次数。无歌词时返回空歌词，不自动触发外部歌词抓取或 AI。`recent` / `frequent` 专辑列表为空。

曲库按歌曲现有歌手署名与专辑名分组（合作署名保持完整）；歌曲 ID 沿用网页，专辑/歌手兼容 ID 从名称确定性生成，改名后变化。首版共享曲库视图每个 Worker 实例缓存 60 秒，最多 10000 首，超出明确报错；每页最多 500，搜索空串可分页同步全库。新增/修改/删除歌曲最多约 60 秒后在目录中反映，媒体读取仍查当前曲库。冷启动与大曲库的实际 D1 成本需部署后测量。

只支持 GET（媒体也接受 HEAD）；返回 JSON/XML，支持 `.view`；除公开扩展发现外，每次请求都验证开启状态与凭据。尚不支持密码参数 `p`、API Key 或 HTTP form POST。非回环地址强制 HTTPS。认证失败有每个 Worker 实例的有限内存限流，非跨实例全局限流；开关密码校验复用现有持久登录限流。

## 用户验收清单

记录 FlareTune 提交号、客户端版本和系统，再逐项确认：

- 开关关闭时无法连接；开启后能登录、浏览歌手/专辑、搜到指定歌曲。
- 能实际听到声音、暂停/继续、拖动进度、连续切歌、显示封面和已有歌词。
- 下载后能离线播放；不支持的音频格式有明确反馈。
- 客户端收藏和取消收藏，在网页刷新后可见，反向操作也可见。
- 创建歌单、添加/移除歌曲、改名、删除；网页与客户端刷新后结果一致。
- 另一账号看不到你的歌单/收藏；普通成员没有管理曲库或账号的权限。
- 关闭开关后新请求失败；改密后开关关闭，旧密码失败，验证新密码并开启后恢复。

反馈时提供操作步骤与去除凭据的错误信息。不要分享完整请求 URL、密码或包含 `t`、`s` 的日志。

## 部署与日志

无需数据库结构迁移；使用现有 `DB`、`MEDIA_BUCKET`、`SETUP_SECRET`。自定义资产路由要将 `/rest` 和 `/rest/*` 交给 Worker。模板关闭包含请求 URL 的 invocation logs，避免 token/salt 落日志；自定义代理、Tail、Logpush 或外部监控也应删除查询参数。部署后先用测试账号验收。后台开关仍受原生会话、CSRF 和账号绑定保护。

参考：[Subsonic API](https://www.subsonic.org/pages/api.jsp)、[OpenSubsonic 扩展发现](https://opensubsonic.netlify.app/docs/endpoints/getopensubsonicextensions/)、[Cloudflare 请求日志](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)。
