# 歌词源配置

[简体中文](lyric-sources.md) · [English](lyric-sources.en.md)

管理员在「设置 → AI 与助手 → 歌词源」管理一个来源列表。内置 LRCLIB 固定启用，不提供编辑、删除或开关。点击「添加源」填写名称、可选备注、搜索／下载地址及来源译文语言，无需选择歌词类型；应用获取后自动识别逐字、逐句或纯文本。可以添加多个独立来源（最多8个），各自编辑、启停及删除。名称用于候选列表辨认，备注仅管理员可见。停用保留配置，删除不删除已保存歌词。弹窗只保存当前来源，取消丢弃草稿；发生配置冲突时刷新页面再打开。

旧版配置读取时自动保留自建源地址和标识，首次保存后写入新版具名列表。LRCLIB 始终使用官方地址 `https://lrclib.net/api`；旧版对它的停用或地址修改不再生效。回滚旧代码时需一并恢复旧歌词源配置快照。

自定义是配置接口地址和来源信息，请求与响应须符合下面的数据格式，不提供任意请求头或脚本编辑器。域名只是示例，填写你自己有权使用的 HTTPS 搜索和下载接口完整地址；不含查询参数、片段或 URL 账号密码，不支持 IP、本地地址、非标准端口和重定向。应用只发送歌曲标题、歌手、时长及候选 ID 等检索数据，不发送登录凭据。接口地址仅管理员可见，成员可以查询启用的来源和歌词。

## 快速测试

在新增或编辑来源的配置弹窗中，先填好地址，再执行快速测试。已有当前歌曲时默认带入歌名、歌手与可用时长；可以重新使用当前歌曲，也可以手填歌名和歌手。测试使用当前未保存的草稿，无需先保存或启用来源。

测试先搜索，再下载解析最多前三个候选，显示候选数量、搜索／下载／解析阶段和耗时；解析成功时显示实际歌词类型、行数及有无译文。没有候选表示本次未命中、下载尚未验证，不能据此判断接口损坏或完整可用。网络、超时、下载或解析失败会显示原因，可以修改输入后重试；修改配置或测试歌曲后须重新测试。

测试不保存来源配置、不修改歌曲或歌词，也不调用歌词 AI；确认配置后仍需点击「保存」。检测结果只有摘要，不包含上游原文、接口地址或候选访问令牌。只有管理员可以执行测试。[Demo](https://flaretune.arcinks.com/settings/admin/assistant) 展示同一配置和测试区，管理项只可查看，不联网取词。

## 搜索与下载接口

例如搜索地址 `https://lyrics.example.com/search`，下载地址 `https://lyrics.example.com/download`。搜索使用 GET，查询参数为 `keyword`（标题和歌手）、`duration`（可用时，毫秒）、`ver=1`、`man=yes`、`client=pc`。响应示例：

```json
{"candidates":[{"id":"track-1","accesskey":"candidate-token","song":"Example Song","singer":"Example Artist","album":"Example Album","duration":200000}]}
```

下载使用 GET，参数为 `id`、`accesskey`（来自搜索结果）、`fmt=krc`、`charset=utf8`、`ver=1`、`client=pc`，返回 `{"content":"BASE64_CONTENT"}`。KRC 内容为 `krc1` 标记与该格式的压缩加密数据；应用解码逐字时间及可用译文。无可用 KRC 时再请求 `fmt=lrc`，内容为 UTF-8 LRC 的 Base64。内容有词级时间时显示逐字，有行级时间时显示逐句，没有时间时显示纯文本；不伪造更高精度。

## 旧版接口兼容

此前已配置的另一种搜索／下载接口继续使用原有数据格式，不需要重建来源或迁移地址。它属于旧来源的内部兼容，新建弹窗不再提供格式选择：

例如 `https://lines.example.com/search` 和 `https://lines.example.com/download`。搜索 GET 参数为 `s`（标题和歌手）、`type=1`、`offset=0`、`limit=10`；响应示例：

```json
{"code":200,"result":{"songs":[{"id":"track-1","name":"Example Song","artists":[{"name":"Example Artist"}],"album":{"name":"Example Album"},"duration":200000}]}}
```

下载 GET 参数为 `id`、`lv=1`、`kv=1`、`tv=1`；响应示例：

```json
{"code":200,"lrc":{"lyric":"[00:01.000]Example lyric"},"tlyric":{"lyric":"[00:01.000]示例译文"}}
```

`tlyric` 可省略，译文通过时间戳与原文对齐。在配置中选择「来源译文语言」，使原有译文与歌词 AI 的目标语言判断一致。每个来源独立保存地址；不符合协议的服务需要由服务端自行转换响应格式。

来源请求与测试都有超时、响应大小和解码上限；失败不会替换已有歌词。候选仍按标题、歌手、版本和时长匹配，管理员可在工作台预览并导入。启停来源不会删除已保存歌词；旧版本歌词继续读取，重新取词只使用当前启用的来源。

多源查询共用有界请求预算，并保留内置 LRCLIB 的回退机会。来源较多时可能达到本次检索的请求上限，界面会将其与上游服务限流区分。已完成的歌词和候选继续保留，可减少查询来源后重试。

LRCLIB 的重复请求会合并，成功的候选摘要短时复用，并控制请求间隔；预览检查与导入仍重新校验。上游限流时遵守 Retry-After，未提供等待时间时默认冷却30秒。候选页和预览显示明确原因与倒计时，等待结束后可手动重试；重试一个来源不会清空其他来源的候选，也不会自动循环请求。第三方服务仍可能拒绝，等待时间不保证服务一定恢复。
